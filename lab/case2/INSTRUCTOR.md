# CASE-0907 풀이와 검산

이 문서는 실습 해설이다. 처음 조사할 때는 증거 입력에 포함하지 않는다.
실제 사건이나 실제 모델의 응답을 재현한 문서가 아니다.

## 입력과 범위

물리 행수는 인증 18·파일 접근 23·전송 12, 합계 53이다. 같은 이벤트의 복제 다섯
행을 구분하면 고유 이벤트는 48이다. 인증 16·파일 21·전송 11이며 인증에는
시작 5·종료 5·거절 6이 포함된다. 사건의 모든 날짜는 2026-09-07이다.

중복 위치는 auth 17→3, 18→11, file 22→8, 23→1, transfer 12→2다.
동일 내용은 원문에 남기고 집계에서만 한 번 센다.

세션은 다섯 구간이다. staff/account-a/work-b/S-200은 09:10~09:25와
10:10~10:20 UTC에 두 번 사용되므로 서로 다른 구간으로 취급한다.
service/account-a/build-a/S-200은 이름 일부가 같아도 다른 계정 영역·호스트다.

## 대상 구간

auth.jsonl:3~4, staff/account-a/work-b/S-200, 09:10~09:25 UTC.

- 파일 8~11행: 허용 4건, 경로 3개, 32768+65536+8192+32768=139264바이트.
- 파일 12행: 거절 1건, 반환 바이트 0.
- 전송 2~3행: 외부 표시 완료 두 건, 65536+65536=131072바이트.
- 전송 4행: 차단 0바이트. 5행: 중단 12288바이트. 6행: 대기 null.
- 외부 표시 알려진 송신 합계는 131072+0+12288=143360바이트, 미확인 1건.
- 전송 7행: 내부 표시 완료 32768바이트, 외부 집계에서 제외.

사용자명만 계산하면 물리 9행·알려진 736256바이트이며, 중복만 분리하면
8이벤트·670720바이트다. 추가로 섞인 다른 영역 524288바이트, 나중 구간 1024바이트,
연결되지 않은 2048바이트를 분리해야 대상 구간의 합계가 나온다.

## 연결 보류

file.jsonl:17(09:09:30)은 시작 30초 전, 18(09:26)은 종료 이후, 19는 호스트가
work-z다. transfer.jsonl:11(09:27)은 종료 이후다. 네 이벤트 모두 삭제하거나
정상으로 확정하지 않는다. 시각 오차·누락 인증·호스트 식별자 자료를 요구한다.

## 판정 한계

자료에는 실제 행위자·인증 수단·정상 업무 요청·파일 내용·전송물 해시·수신자 보유
기록·독립 시계 검증이 없다. 계정 침해와 실제 외부 유출을 확정할 수 없다.
같은 ZIP 이름과 크기의 완료 작업 두 개를 같은 내용의 재시도로 확정하지 않는다.
139264바이트는 고유 파일 용량이 아니며 143360바이트는 고유 유출량이 아니다.

수동 fixture·SQLite 독립 계산·잘못된 오프셋·동일 ID 충돌·중복 키·숫자형 오류·경계
시각·기존 출력 거부·입력 보존 시험을 통과해야 한다. 시험의 정상 종료와 실제 침해
판정의 정확성은 별개다. 보고서 예시는 18장을 참고하되 실제 관측 범위를 넘어선
행위자·목적·전송 내용은 채우지 않는다.
