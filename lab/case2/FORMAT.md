# case2/v1 입력·출력 명세

이 형식은 17·18장의 합성 사건을 위한 자체 형식이다. 실제 제품의 로그 형식이
아니며 Windows, macOS, 인증 서비스, 파일 서버의 공식 이벤트를 변환한 것도 아니다.
모든 계정·호스트·경로·시각은 허구다. 로그 안의 문자열은 실행 지시가 아니다.

## 입력 파일과 부호화

증거 폴더에는 `auth.jsonl`, `file.jsonl`, `transfer.jsonl` 세 일반 파일만 둔다.
UTF-8 JSON 객체를 한 줄에 하나씩 기록한다. 생성기는 LF와 마지막 줄바꿈을 사용한다.
분석기의 행 번호는 물리 행을 1부터 센다.

JSON 키 순서는 의미가 없지만 같은 객체
안에 중복 키는 허용하지 않는다. 빈 줄, 숫자의 NaN·Infinity, 문서화하지 않은 필드는
거부한다. 실제 JSON 표준 설명은 [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)를 참고한다.

한 파일 16 MiB, 한 줄 65,536바이트, 한 파일 100,000행을 상한으로 사용한다.
이 제한은 교육용 입력 크기의 제한이며 모든 자원 고갈이나 경쟁 상태를 막는 보안
장치가 아니다. 심볼릭 링크인 증거 폴더와 입력 파일은 받지 않는다.

## 공통 필드

| 필드 | 값과 의미 |
|---|---|
| `schema` | `case2/v1` |
| `source` | 파일별 `case2-auth`, `case2-file`, `case2-transfer` |
| `event_id` | source 안에서 이벤트를 식별하는 문자열 |
| `event_time` | 기록자가 표시한 이벤트 시각. 초와 명시적 오프셋 필수 |
| `realm` | 계정 영역 식별자. 다른 영역의 동일 이름은 구별 |
| `user` | 계정 이름. 실사용자의 신원을 입증하지 않음 |
| `host` | 활동 호스트의 식별 문자열. 자동 별칭 대응 없음 |
| `session_id` | 호스트가 사용한 세션 이름. 호스트·시간에 따라 재사용 가능 |

식별자는 영문자·숫자·밑줄·마침표·하이픈으로 된 96자 이하 문자열이다.
`session_id`는 거절 로그인에서만 빈 문자열이다.

시각은 `YYYY-MM-DDTHH:MM:SSZ` 또는 `YYYY-MM-DDTHH:MM:SS±HH:MM`만 받는다.
오프셋은 시 00~23·분 00~59이며 `-00:00`은 현지 오프셋을 알 수 없다는 의미이므로
거부한다. 날짜·시각이 실제 달력에 존재해야 한다. 소수 초·윤초·오프셋 없는 시각은
지원하지 않는다. [RFC 3339](https://www.rfc-editor.org/rfc/rfc3339) 전체의 구현이 아니다.

UTC 변환은 시간대 표기를 맞추는 절차이며 시계 정확성의 독립 검증이 아니다.

## 인증 파일

추가 필드는 `action`, `outcome`, `client_ip`다. 다음 조합만 허용한다.

| action | outcome | session_id | 의미 |
|---|---|---|---|
| `login` | `denied` | 빈 문자열 | 접속 거절. 이유·인증 수단은 제공하지 않음 |
| `session_start` | `allowed` | 비어 있지 않음 | 이 키의 세션 시작 |
| `session_end` | `closed` | 비어 있지 않음 | 이 키의 세션 종료 |

`client_ip`는 접속 요청의 IP 주소다. 실제 행위자 위치나 장치 소유자가 아니다.
프로그램은 유효한 IP 문법을 검사하며, 배포 생성기는 문서용 예약 주소만 사용한다.

## 파일 접근 파일

추가 필드는 `action=read`, `path`, `outcome`, `bytes_returned`다.
`outcome`은 `allowed` 또는 `denied`다. `path`는 `/`로 시작하는 1,024자 이하의
기록 문자열이며 실제 파일을 열지 않는다. `bytes_returned`는 0 이상 2^53-1 이하의
정수이고 불리언은 숫자로 받지 않는다. 거절된 읽기는 반드시 0이다.

바이트는 기록자가 반환했다고 표시한 요청별 양이다. 고유 파일 크기·고유 내용량을
뜻하지 않으며, 파일 내용·해시·버전·읽기 오프셋은 제공하지 않는다.

## 전송 파일

추가 필드는 `transfer_id`, `state`, `destination_zone`, `destination`,
`destination_ip`, `declared_bytes`, `bytes_sent`, `artifact`다.
전송 ID·대상 이름·전송물 이름은 비어 있지 않은 1,024자 이하 문자열이다.
대상 IP는 문법을 검사한다. `destination_zone`은 전송 프로그램의 설정상 분류인
`internal` 또는 `external`이며 실제 네트워크 경계를 측정한 값은 아니다.

`declared_bytes`는 작업이 선언한 크기이고 `bytes_sent`는 프로그램이 송신했다고
기록한 양이다. 숫자는 0 이상 2^53-1 이하 정수이며 다음 제약을 적용한다.

| state | bytes_sent | 의미 |
|---|---|---|
| completed | declared_bytes와 동일 | 프로그램의 완료 상태 |
| blocked | 0 | 해당 작업의 송신 전 차단 기록 |
| interrupted | 0~declared_bytes | 완료되지 않은 작업의 알려진 송신량 |
| queued | null | 이 기록에서는 송신량을 알 수 없음 |

같은 전송물 이름·크기는 같은 내용이나 재시도를 입증하지 않는다. 전송 ID별 이벤트는
이 버전에서 하나의 상태만 표현하며 후속 상태 이력은 제공하지 않는다. 실제 전송 작업의
상태 전이 로그를 다루려면 전송별 최종 상태 선택과 중간 누적 바이트 처리 명세가 별도로
필요하다. 이벤트별 값을 그대로 합산하는 이 파서를 누적 카운터 로그에 적용하지 않는다.
프로그램의 완료와 수신자 보유 또는 실제 외부 유출은 동일한 판정이 아니다.

## 중복과 세션 연결

중복 키는 `(source, event_id)`다. 같은 키의 전체 필드 값이 같으면 한 이벤트로 세고
원문 위치를 모두 보관한다. 같은 키에 내용이 다르면 충돌로 중단한다. 기록을 삭제하거나
덮어쓰지 않는다. 전송물 이름이 같은 서로 다른 이벤트는 이 기준의 중복이 아니다.

세션 키는 `(realm, user, host, session_id)`다. 시작을 포함하고 종료를 제외하는
`start <= event_time < end` 구간에 같은 키의 이벤트만 연결한다. 종료한 뒤 같은 키가
다시 시작하면 다른 구간이다. 시작 이벤트의 `파일명:행번호`를 분석상의 `instance`로 쓴다.
이 값은 원래 세션 ID를 대체하는 제품 식별자가 아니다.

겹치는 시작, 시작 없는 종료, 양수가 아닌 구간 길이는 오류다. 종료가 없는 시작은
열린 구간으로 남고 `open_session_windows`에 표시한다. 열린 구간 안의 연결은 실제
세션이 계속 유효했다는 입증이 아니라 제공된 기록에 종료가 없다는 조건을 가진다.

키가 없거나 시각이 구간 밖이면 `unlinked`로 남긴다. 미연결은 정상·오류·악성 판정이
아니며 현재 규칙으로 연결하지 못했다는 결과다. 오차 허용 범위를 임의로 붙이지 않는다.

## 분석 산출물

`analyze.py --evidence DIR --out NEWDIR`는 아직 없는 별도 결과 폴더에 다음을 쓴다.

| 파일 | 내용 |
|---|---|
| summary.json | 입력 파일별 해시·크기·행수, 중복, 세션별 합계, 미연결, 제한 사항 |
| timeline.jsonl | 고유 이벤트의 원문 객체·UTC·모든 원문 위치. 시각순 정렬 |
| links.jsonl | 파일 접근·전송별 대표 원문 위치·연결 구간·연결 또는 보류 이유 |
| claim-checks.json | 실제 행위자·계정 침해·수신자 보유·고유 유출량 등의 미확정 표시 |

같은 초에서는 원문 위치를 보조 정렬 기준으로 사용한다. 이는 결정적 표시 순서이며 실제
실행 선후관계가 아니다. `claim-checks.json`은 보고서 문장을 자동 판정하는 검출기가 아니다.

`external_known_sent_bytes`는 연결된 외부 표시 이벤트의 숫자 `bytes_sent` 합계,
`external_completed_sent_bytes`는 그중 완료 상태만의 합계다. null은 더하지 않지만
`external_unknown_byte_events`로 개수를 반드시 함께 표시한다.

입력은 초기 읽기와 출력 전 두 번째 읽기의 해시를 비교한다. 값이 다르면 중단하지만
그 사이 변경 후 원상 복귀나 두 번째 검사 이후 변경은 탐지하지 못한다. 운영체제 권한과
격리·수집 기록을 대체하지 않는다. 저장 도중 I/O 오류로 부분 결과 폴더가 생기면 그
폴더를 재사용하지 않는다. 종료코드 0은 문서화한 계산의 완료이며 침해 판정의 정확성 보증이 아니다.

## 주소와 도메인

생성 데이터는 [RFC 5737](https://www.rfc-editor.org/rfc/rfc5737)의 192.0.2.0/24,
198.51.100.0/24, 203.0.113.0/24 주소와
[RFC 2606](https://www.rfc-editor.org/rfc/rfc2606)의 example.com·example.net 아래 이름만 쓴다.
이 이름으로 네트워크 연결·평판 조회를 실행하지 않는다. 생성기와 분석기는 네트워크를 사용하지 않는다.
